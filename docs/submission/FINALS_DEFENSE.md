## 答辩问答预案（评委高概率问题）

| 问题 | 要点 |
|---|---|
| 与上游 Mooncake Store 的区别？ | 聚焦单实例分层淘汰/预取协同；上游 Transfer Engine 被复用而非重写；机制可回馈上游 |
| 为什么不用 SIEVE/更新的策略？ | 跨容量扫描显示容量敏感（小缓存 −1.5pp），有负结果数据支撑 |
| 命中率提升如何换算成真实收益？ | 每命中一块省一次 prefill（模型：4ms/块）；TTFT p50 −71% 即由此而来；RTX 5090 在线实测已验证（卸载 TTFT 2.4×；三层 NVMe 再 2.2×，ShareGPT 真实负载 2.9×；S3-FIFO 较 LRU mean −10～11.5%） |
| 多实例/分布式怎么办？ | 设计论证已完成（docs/analysis/distributed-design.md）：会话锚一致性哈希保前缀聚居，单机不变量逐条保持，既有控制面原语（跨节点索引/公平配额/故障转移）直接复用；幽灵统计经分析本地化即可 |
| 测试如何保证正确性？ | 属性测试（不变量：容量守恒、命中即存在、降级链完整）+ 三消毒器 + 确定性回放逐位对比 |
